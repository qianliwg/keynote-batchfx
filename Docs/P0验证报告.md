# Keynote 动效工坊 P0 验证报告

验证日期：2026-10-20。结论：应用基础和三个专项实验已落地，允许进入 P1；逐帧误差目标仍待专项测量，不能据此宣称正式动画编辑器已经完成。

## 交付内容

- `Backups/P0-2026-10-20/Keynote动效工坊-P0.zip`：P0 原生 arm64 macOS 应用备份。
- `Backups/P0-2026-10-20/Keynote动效工坊-P0-source.tgz`：P0 源码备份。
- `KeynoteAdapter`：独立 JSON 协议进程，负责读取 Keynote、检查媒体、生成校验副本。
- `ProjectFormat/project-v1.schema.json`：后续多组动画、时间线和资源管理共用的项目格式草案。
- 原有 `Keynote沿线动画工具` 1.1 保持原样，作为兼容基线。

应用内置 CPython 3.13.7 arm64 运行时，适配器以隔离模式启动，不依赖电脑上另装的 Python。应用窗口可打开文稿、运行几何自检、生成校验副本，并打开三个原生样例。样例入口会复制一份到临时目录再交给 Keynote，避免自动保存修改应用包。

## P0 几何与数据验证

- 1001 个非中心锚点姿态通过几何检查，物体位置误差小于 `0.000001` 点。
- 两次停靠、三段速度使用同一个时间函数，路线和物体的分段进度一致。
- 贝塞尔曲线拆分的接点连续；这是生成器的几何保证，不把它表述为 Keynote 的逐帧保证。
- 图片资源按字节指纹校验；复制文稿时先写临时包，再一次性发布，避免生成半成品副本。

## 当前边界

P0 是可运行的应用骨架和原生兼容性验证，不是完整的时间线编辑器。预览进度条、贴线点与工程保存属于 P1，多组动画和节奏属于 P2，反向/往返/循环和群组编辑属于 P3，签名公证属于发行阶段。当前贴线实验使用辅助支点组来验证非中心锚点，后续会把它变成用户可直接选择的锚点设置。

对分段描线而言，共用分段时间并不自动证明任意时刻的笔尖位置一致。P1/P2 必须测量 Keynote 原生插值与预览弧长模型之间的差异，未达到目标前保留实验标记。

## 重复验证

```text
python3 -m unittest discover -s Keynote沿线动画工具/tests -v
python3 Keynote动效工坊/Verification/test_adapter.py
Keynote动效工坊/Packaging/build.sh
```

现有 1.1 的 7 个回归测试通过；新适配器 5 个集成检查通过，覆盖独立运行时、嵌套群组与中文素材的完整复制、拒绝覆盖已有文件、拒绝来源变化和协议错误。原有 1.1 源码与两份示例的 SHA-256 与基线一致。

应用实际启动并通过界面中的“运行自检”。构建脚本编译、签名、执行数学自检，并对 ZIP 在独立临时目录解包后验证签名；ZIP 条目使用显式 UTF-8 文件名标记，中文 `.app` 名称不会依赖系统 locale。当前同步工作区可能重新给 `.app` 根目录附加 `com.apple.FinderInfo`，因此保留干净的 ZIP 作为分发基准；它与 Python 运行时无关。

应用使用本地临时签名，最低编译目标为 macOS 14、仅 arm64，当前仅在本机验证。发布给其他 Mac 前还需要开发者证书签名、公证和安装包流程。
